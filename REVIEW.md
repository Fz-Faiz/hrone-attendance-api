List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 56–58) | Static `{"status": "ok"}` response without checking MongoDB connectivity; never returned 503 when the database was down. | Healthcheck test while MongoDB is stopped or connection refused; returns 200 instead of 503. | Added active `db.command("ping")` probe, raising HTTPException 503 on database unavailability. |
| 2 | Startup / Indexes (missing) | No database indexes were defined or initialized, permitting duplicate employee codes and attendance natural key collisions, and causing unindexed COLLSCANs. | Concurrent duplicate employee/punch creations succeed; `explain` executionStats reports COLLSCAN. | Implemented `init_db_indexes()` in FastAPI lifespan with unique constraints on `emp_code` and `(emp_code, date)`, plus compound query indexes. |
| 3 | `to_epoch_ms` (lines 44–53) | Naive datetime conversion (`dt.timestamp()`) without explicit UTC enforcement produced local-system timezone shifts; inconsistent null handling. | Converting known UTC datetimes produced offset millisecond values depending on local machine timezone. | Replaced with strict UTC-aware conversion (`replace(tzinfo=timezone.utc)` for naive datetimes) returning integer epoch milliseconds. |
| 4 | `compute_late_minutes` (lines 78–83) | Evaluated `diff_sec >= 600` instead of `> 600` (violating 10:00 grace rule R2), and deducted grace period (`diff_sec - 600`) instead of calculating floor minutes from shift start. | Punch-in at 09:40:01 IST gave 0 minutes instead of 10; 10:15:59 IST gave 35 instead of 45. | Changed threshold to `diff_sec > 600` and returned `math.floor(diff_sec / 60)` elapsed from shift start. |
| 5 | `compute_work_hours` (lines 86–88) | Float division using Python built-in `round()` applied banker's (round-half-to-even) rounding instead of half-up rounding (R4). | Durations ending in `.xx5` rounded downward to even digits instead of upward. | Used Python `Decimal` arithmetic with `ROUND_HALF_UP` quantized to two decimal places (`0.01`). |
| 6 | `compute_overtime` (lines 91–95) | Assumed daytime shifts only; failed for overnight shifts (`shift_end <= shift_start`) where shift end falls on the following calendar day. | Punch-out at 06:45 IST on overnight 22:00–06:00 shift produced negative or corrupt overtime. | Adjusted shift end calendar date to `att_date + timedelta(days=1)` for overnight shifts before computing minutes (threshold >= 30 per R3). |
| 7 | `create_employee` (lines 102–111) | Missing input validation (regex for `EMP\d{4,6}`, valid email, HH:MM shift times, `shift_start != shift_end`); client-set or missing `created_at`; exposed MongoDB `_id`; duplicate codes allowed. | Invalid payloads passed validation; duplicate codes overwrote documents or created duplicates without 409 Conflict. | Added strict Pydantic `EmployeeCreate` schema, server-clock `created_at`, unique index enforcement catching `DuplicateKeyError` to return 409, and stripped `_id`. |
| 8 | `list_employees` (lines 114–124) | Department filter used regex instead of exact match; no ascending sort by `emp_code`; incorrect pagination (`skip = page * page_size` skipped page 1); `total` counted unfiltered collection; exposed `_id`. | Querying `page=1` skipped the first page of results; filtered count returned global collection count. | Applied exact case-sensitive department filter, sorted by `[("emp_code", 1)]`, fixed `skip = (page - 1) * page_size`, returned filtered `count_documents`, and serialized output. |
| 9 | `punch_in` (lines 132–158) | Accepted invalid/string/second timestamps; did not verify employee existence (no 404); ignored overnight shift rules (R1); did not truncate subseconds; check-then-insert lacked concurrency safety. | Unknown employee accepted; 01:00 overnight punch tagged wrong date; concurrent duplicate punches both succeeded. | Added strict epoch ms validation, 404 employee check, R1 IST calendar/overnight adjustment, subsecond truncation, and atomic natural key uniqueness (409 on conflict). |
| 10 | `list_attendance` (lines 161–177) | Did not validate `date_from <= date_to` (returned 200 instead of 422); lacked required sort (`date` DESC, `emp_code` ASC); exposed `_id`. | Passing inverted date ranges did not error; response order was arbitrary insertion order. | Added 422 validation for inverted date ranges, enforced compound sorting `[("date", -1), ("emp_code", 1)]`, and serialized output. |
| 11 | Missing Endpoints (lines 180+) | Entirely omitted endpoints: `POST /attendance/punch-out`, `PATCH /attendance/{emp_code}/{date}`, and all analytics/admin endpoints. | Endpoints returned 404 or unhandled errors. | Implemented all endpoints per OpenAPI contract and business rules R1–R10. |

### Considered and Decided Not a Defect:

1. **MongoDB `_id` Generation**: MongoDB automatically generates BSON `ObjectId` for `_id` on every insert. This is normal database behavior and not a defect, provided `_id` is never serialized or leaked into client HTTP responses.
2. **Strict Inequality on Half Day (`work_hours < 4.50`)**: Rule R5 specifies half day is true when work hours are strictly less than 4.50 (not `<=`). Keeping strict inequality is exact contract compliance.
3. **No Direct Creation Endpoint for `ABSENT` / `LEAVE`**: Punch endpoints only create presence records (`PRESENT`, `WFH`, `ON_DUTY`). `ABSENT` and `LEAVE` records exist through initial data seeding or manual administrative regularizations (`PATCH`), which matches the design contract.
